# HybridOps Architecture

## Data flow

1. The workload baseline pipeline produces a JSON payload containing forecast metadata, model performance, and tasks.
2. Django stores the entire payload in `DataImport.raw_payload`.
3. Each task is normalized into `WorkloadForecast`. Missing bandwidth is estimated deterministically and marked as `estimated`.
4. The carbon baseline pipeline produces region/hour forecast rows. Django stores both the raw payload and normalized `CarbonForecast` rows.
5. Infrastructure JSON is retained in a raw import and normalized into editable environments.
6. A scenario maps carbon forecast zones to infrastructure geographies and supplies objective weights and targets.
7. Gurobi builds placement decisions and returns a structured `OptimizationRun` plus `TaskPlacement` rows.
8. React loads all dashboard views through the Django REST API.

## Baseline preservation

The supplied notebooks are not edited. The application accepts their existing JSON output shapes. Production forecasting modules should be generated by extracting notebook cells without changing feature engineering, train/test splitting, model selection, hyperparameters, or output calculations.

The finalized portal does not bundle sample operational data. It synchronizes
the versioned workload, carbon, infrastructure, and optimization artifacts
produced by `hybridops_core`, and stores raw payloads plus normalized records
in PostgreSQL.

## PostgreSQL ownership

PostgreSQL is the only application database. It stores:

- raw source JSON
- normalized workload and carbon forecasts
- infrastructure and administrative configuration
- scenarios
- optimization inputs and outputs
- placement decisions and KPIs

No SQLite configuration or fallback is included.
